## 本轮实体

源文件 `massif_cirque_wall_cirque54v2.blend`，GLB为交换副本，`cirque54v2-payload.json`为分件/顶点色/世界三角数据。4个可编辑闭合分件、1554三角：重塑后的整座cirque主体862、宽下沟雪A360、宽下沟雪B284、上部雪洼48。作者峰高目标185m，受原岸线坡度约束后最高雪面179.4199m。

完整上部按分级宽肩重新塑形，结合原水线距离限制陡起，两条沟采用宽缓横断面。保留的低根最高跨水端仅74.0724m；没有继续为保存全部旧692三角而叠231m高盖。

本轮实际重新看了原1128/1129以及54v1四张实际世界图。v1在近观中显出巨大灰墙、单高块及窄V雪夹缝，明确不通过并全部保留。本v2尚待五面，不能用几何数量或通过的保护证明预判造型。

## 水下与保护范围的最终做法

最初尝试对原三角在Y0精确分割。attempt-a因CDT凹边界填面与共线点简化造成闭合失败；attempt-b修好闭合，但水线切点写入原生float32后出现最大1.4572e-5m舍入，严格原湿面等价没有通过。两稿源、日志及诊断均保留，没有放宽门。

随后采用更强保护：432个触水/水下原三角整个保留，沿42条原生正高边重塑其上方260个干面；其中19个与建筑保护区相交的干面也整面保留，实际改形限于其余区域。无需序列化新的水线切点。

颜色核对时还发现 `Mesh.get_faces()` 的派生顶点与保存资源原始ArrayMesh数组存在末位差异：890个展开点不同，其中106点Y≥0，最大三维距离0.0001230203m。**原CollisionShape数组与GPU原始数组逐float32完全一致**。最终权威因此使用保存53的原始GPU数组与原碰撞数组，而不再使用派生Mesh.get_faces作源几何权威。完整地形支承查询原本就使用CollisionShape数组，未受影响。

最终新进程Blender重开验证：

- 432个触水/水下原三角的有向float32位置和RGBA完全一致，数量432对432；没有新触水三角。原Y0交线、湖切口及全部湿面由相同完整原三角定义，保持不变
- 19个建筑保护干面各自整面有向float32位置与RGBA完全一致，没有用重新三角化的近似面冒充原面锁定
- 四分件原生重开几何/RGBA逐float32匹配payload；边界边、非流形边、退化面均0，体积均正
- 完整171建筑点与原53真实物理报告对照，完整原场景查询误差≤0.0006104m，本源造成支承变化0
- 当前53的1261落位中109项根支承改变、1152项根支承未变；53west既有120项均无新支承变化。尚未完成树冠/岩石实际mesh体积影响，因此109只是观察集，未迁移任何实例

证据：`native-reopen-water-support-proof.json`、`native-color-preservation.json`。

## 连续域与自交

`continuous-modified-domain-proof.json` 以完整1096个非水layer4形体为来源，用精确原三角字节比较区分新/改形面与原样保留面。所有新/改形面和雪层完整投影都包含在实际干地并集内，差集面积最大约1.42e-25m²，低于一直使用的1e-8m²数值门；与19个实际保护矩形正面积交集全部0。原湿面另由原生三角严格相等证明保护。

`actual-triangle-self-intersection-proof.json` 在新Blender进程重开本源，对各分件实际三角分别检查：穷举AABB候选共21092对，float64精检原生float32顶点，四件均无自穿插/正面积共面重叠；两个阳性、两个阴性对照全部正确。四个残余共面零面积候选另经GEOS距离确认实际分离，最小1.8504m。分件之间有意埋入未混算为自交。

## 真实三角覆盖诊断及其严格限制

`analyze_coverage52f.py` 使用52e诊断器的真实GLB三角并集，25个原51b/52e根的原始变换、相同345×345采样格和原1216机位。它没有填AABB/凸包，也没有修改世界文件。

本阶段只有v0连接体。下面的数字把这一件原型原样放在全部25个根下，配合各根原52e三变体，检查尺寸是否有效；它不是已完成的三变体安排。每根的原3件均不改动，原75冠体的位置和世界最高点保留。

| 诊断 | 原52e | 单连接体重复布局 |
|---|---:|---:|
| 内部俯视三角覆盖 | 35.24% | 58.08% |
| 最大连通空白采样面积 | 7.708km² | 2.300km² |
| 1216正面下半屏覆盖 | 54.47% | 79.22% |
| 1216侧面下半屏覆盖 | 66.28% | 88.94% |
| 1216背面下半屏覆盖 | 59.02% | 74.58% |

这仍达不到70–85%的试验诊断范围；正面也未达到85%。实际查看诊断高度图后，仍能看到大块连续跨根空白。第二件低漂流体及邻接处调整仍有必要，但必须先看当前原型五面。不得靠重复同一长条机械补满。

诊断图不含其他对象、材质、光照、深度遮挡或飞行碰撞，不是渲染图、参考相似度或视觉验收。完整来源和限制在 `coverage/coverage-report52f-prototype.json`。

## 交给父任务的五面预览

由父任务安排图形槽，运行：

```sh
python source-assets/cloud-sea52f/run_preview52f.py
python source-assets/cloud-sea52f/run_preview52f.py --isolated
```

默认渲染原52e v0三件＋新连接体五面；`--isolated` 单看连接体五面。可附 `--white` 做纯色形体诊断，仍不保存。只允许v0，避免假装三变体已完成。相机、灯光、20 samples CPU4线程及1950m正交宽度均沿用52e条件；900×640图、输入/输出SHA、退出码和保护源前后SHA落独立cloud-evidence目录。只读相机预检已通过五面，边距见 `camera-framing-preflight.json`。

必须实际查看组合和单体的正、侧、背、上、下方，重点否决：过长光滑条带、统一底盘、近等高碗底、少量巨大圆球、薄颈穿插接缝。审形通过后才扩展第二体及三种独立布局，重新算覆盖并决定是否可进入有限世界试验。

# F2：九处局部高度重排，等待实际两图

F 的原生源和失败证据全部保持原样。F2 是独立候选，仍是假设；当前
只准备代码与静态自检，没有启动 Blender，没有原生 F2 源或实际图片。

## 最小设计范围

保留 F 原设计尺度、整块位置、全部 X/Z、顶冠的63点、拓扑及11个编辑组。
只改六个下返高度、一个配对腰部高度和两个内腹高度。新下返高度分别为
503、585、595、590、587、571米；两个内腹高度为545、580米。它们不是
同一高度平面，也没有按投影边界硬裁。station22 的高度序列由
675→633→575→517 改成675→633→610→587米，保留连续短折返。

这次仍可能出现大平腹、硬岩块或单调折带。只有真实前/侧后两张图才能
判断；静态留边、连续索引或三角计数都不能支持造型接受。

`patch58f.py` 只把原F构造器读入私有内存，然后应用九项显式高度改动。
`source58f.py` 是薄适配器，直接调用冻结的F原生构建/渲染代码；不复制
旧blend、图像或素材。沿用内部VIEW58F/EDIT58F标签及`*58f.json`报告名，
F2身份由本目录、CloudBank58F2主网格和`shared_patch58f2.blend`明确区分。

## 原身份与门限

- 固定E的原1216前相机及shared-side-back相机矩阵、投影、分辨率
- 固定原材质、太阳、世界、色彩转换；CPU2、8 samples、无去噪
- 侧后实际全部顶点仍须至少7%留边；失败保存源后停止，绝不自动重构图
- 每张图均用不同新进程重新打开已保存源，检查网格、编辑组、相机和光材
- 不加载Game61，不改变默认场景，不做最终自交/连续谷带/硬件GPU验收

## 执行与证据

父任务安排窗口前不运行Blender。随后使用：

```sh
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python3 -B \
  source-assets/cloud-bank58/revision-f2/run_patch58f2.py \
  --run-approved-patch-trial
```

总上限30秒、CPU2、RSS1.5GiB，顺序build→front→side-back；首个失败立即
停止。每阶段写实际退出码、elapsed、观察峰值、wait4取得的独立child实际
峰值，以及原输入SHA清单的摘要。新建唯一证据目录，保存全部日志和部分
成果；不重复覆盖已有F2源。全部旧C/D/E/F输入及准备输入在运行前后核SHA。

## 2. 另路实际几何检查

另路程序直接读取 candidate 与源外岸数据，没有导入作者的 geometry58l、prepare_candidate58l、poly58k 或 native helper 来得出以下结论。

### 2.1 外岸、共享盘和闭壳

1. 从冻结 `design-v3/external-rim.json` 相邻源边重算有理交点，平行时核唯一共同原端点；独立所得 203 点 float64 外环与候选 authority 逐数相等。没有取凸包、平均焊接或删凹湾。
2. 对真实 float32 本地坐标映回的 XZ，统一转成精确二进有理整数；逐面正向面积、边邻接、边相交/共线重叠用整数精确判定。2449 条平面边的 12,454 个 AABB 候选对均通过。全部三角精确有向面积之和与规定非凸外环精确面积相等，最小三角二倍投影面积为 0.753759928047657 m²。
3. 直接从 3130 原面建立 4695 边/1567 顶点邻接：单组件、每边恰两面且相反方向；每个顶点 link 都是单一闭环。Euler=2，结合这些条件为 genus 0，不仅凭 Euler 下结论。
4. 上下片 XZ 相同、内点严格正厚、只在共用简单外环会合。结合无重叠平面盘和闭壳/link 证明，本有限高度场没有额外自交。拓扑、XZ 和绕序在以下所有有限状态保持相同；每态另外检查严格内域厚度与正体积。
5. 默认独立有向体积 290,963,717.0536497 m³，与作者值的浮点求和差约 0.0000011 m³，不作逐位同一宣称。

### 2.2 原空间门没有放宽

没有采用作者的整个三角分类，也没有调用作者裁剪函数。对每个实际仿射三角分别构造 `560-B > 0`、`B-630 > 0`、`120-(T-B) > 0` 区域，以 Fraction 对原边参数及裁剪顶点作精确计算。数值筛选一个真实外岸线段后，逐裁剪顶点到该同一线段的距离平方再次完全用 Fraction 判定 `<6400`。到一个凸线段的距离为凸函数，故凸违规子多边形的最大距离由顶点上界覆盖；该上界也覆盖到整个真实 Γ0 的距离。因此不是只测顶点/采样，也不把原内部孔或接缝当外缘。

默认有 749 个非空违规子多边形，全部严格在真实 Γ0 的 80 m 内；最大上界 77.93207968880053 m。这与把整三角归类为 1186 守门/379 回转三角不矛盾：同一三角可能产生多个违规子多边形。

### 2.3 数值/曲线边界仍保留

## 4. 三个原生准备阻点与最小反证

下面全部为纯内存/静态检查。没有运行 runner main、没有 engine、没有真实原生报告，也未写临时 evidence。反证用于验证现有检查能否分辨错误，不能当 native 事实。

### R1：完整 raw 试验未绑定规定的实际状态

位置：`run58l.py:53–74 validate_exercise`，尤其 58、62–64、71–73。

58 行核的是 probe 的 `id/field/value` 元数据。62 行 `validate_capture` 确实完整核对某份 raw 与其自身所宣称参数的几何/属性/法线等一致，但没有核 raw 的完整 control/secondary 数值是否恰是该标签规定的试验状态。63 行只需非 baseline 并能恢复，64 行按 raw 自己的状态再算空间门。因此“反复验证同一个真实响应状态”可以冒充“七个不同控制都已试验”。

最小纯反证：保留完整 `native_support58l.validate_capture` 原函数未 mock；使用既有四面体纯 fixture，构造合法 C0=1、其余主控制=0、width=1 的完整 raw/法线/属性。所有 8 个 probe 标签和值仍各自符合 specs，但 moved 全部引用这同一 C0 raw。manual 的 combined 直接与 manual 完全相同，根本没有加 C0 控制。仅以内存替代文件读取/哈希，并使用明确标识的 fixture-only 几何 oracle（不是实际候选核心证明）。实际 `validate_exercise` 返回：

`{"controls":7,"secondary_parameters":1,"manual_edit_preserved":true,"exact_identity_restored":true}`

这说明其状态绑定缺口，不是声称原 native 代码已实际执行错误控制。原 `native58l.exercise` 确实逐个设置控制，但独立验收不能只依赖这段实现自称做到了。combined 也未独立重算空间门。

最小修复范围：为每个试验构造完整期望主/次控制状态，逐项与 actual raw 比较；要求 manual 为 defaults、combined 为明确的 C01 exercise+手工基底；对 combined 实际 raw 另算空间门。补“错控制/额外控制/未变化 combined”负控，不要求新增参数扫描。

### R2：views 不保护已存在的 source 准入与终态

位置：`run58l.py:15 MUTABLE`、`17–27 protected_manifest`，尤其 25 行；83 行只在 views 开始时读一次原 source 终态。

MUTABLE 无条件同时排除 source 和 views 两阶段的 attempt/terminal。FINAL_SHA256 冻结发生在原生前，也不包含未来的 source evidence。故 views 阶段 source-attempt/source-terminal 在 before/after 清单之外；子过程期间被改动不会由该保护门发现。当前阶段 admission 文件同样只在 child 启动时读，缺少单独全程固定身份。

最小无写盘反证：向实际 protected_manifest 提供模拟目录 inventory，包含 `source-attempt.json`、`source-terminal.json`、`views-attempt.json`、`views-terminal.json`、`prior-evidence.json`。只 mock os.walk/is_symlink/sha；原函数实际输出仅 `prior-evidence.json`。既有 source 两证据确实没有被包含。未篡改任何真实文件。

最小修复范围：按当前阶段和实际新输出精确豁免；既有 source attempt/terminal 必须进入 views 保护；已写好的当次 admission 也单独绑定并前后核同。继续允许当前新终态和该次新 evidence 目录正常写入，不要求重复备份原包。

### R3：最后源哈希与终态写盘不计入真实总预算

位置：`run58l.py:106` 留 20 秒；`main` 的 finally 尾 `143–150`。

143 行关 alarm，145 行取 elapsed，146 行判断上限。随后 147 行再次完整 hash 源，再在 150 行写/flush/fsync 两份终态及 exit-code。实际总耗时和 watchdog 都已停止覆盖这些操作，可能越过 120 秒仍记成功。20 秒目前只是分配 child 时间时扣除的余量，不等于最后操作也受到完整上限约束。

最小无写盘反证：从冻结源原样提取 143–150 的尾代码，在独立内存命名空间直接执行；进入时模拟 monotonic=119.9，sha耗1秒、两次原子写及 exit-code 各耗0.2秒，无 engine、无真实 sleep/文件写。原尾实际产出：

- 记录 `total_wall_seconds=119.9`
- 实际模拟结束 `121.50000000000001`
- `passed=true`

这不是要求无限完善所有 OS 故障报告；只是当前原定 120 秒预算能被正常尾操作漏计。最小修复应让重型收尾与最后判定仍受明确截止约束，计入真实末尾时间；超预算必须失败且保全已有证据。不要通过放宽 120/80/30/27 门或添加 fallback 绕开。

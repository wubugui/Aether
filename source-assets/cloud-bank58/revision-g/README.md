# 58G：有限支撑多中心连续云体，单小patch准备

当前只准备源码和纯numpy/语法/静态投影自检。**没有启动Blender，没有G的
`.blend`或PNG，也没有视觉结论。** D/E/F/F2失败源、实图与全部旧证据保持
冻结；本项不改Game61、默认入口或权威进度文档，不自行Git或Slack交付。

## 与旧构造不同在哪里

`controls58g.json`给出八个明确可编辑控制：宽偏心主冠、较低后冠、埋入两冠
的宽斜向连接核、前低肩、右中肩、前左下腹、后右下腹，以及仅一个左前小
转向肩。所有米制位置、半轴与强度都是新的设计假设，不是从1216二维图
测出的真实三维尺寸。源坐标沿用原D锚点和U/V/Y方向，不整体缩放/移动拟合。

每个核在旋转椭球内贡献正密度 `strength * max(0, 1-q²)^3`，支撑域外为零；
相加后取0.125等值面。名义半轴乘sqrt(2)得到支撑半轴，因此单独强度1核的
名义半轴对应其等值面。主冠与肩腹宽重叠，核心不充当底盘；没有负场刻沟、
统一高度衰减、全局截底、纬圈、噪声或旧网格改形。

初稿两个下腹曾在未冻结的内存静态试算中取Y=619/635。当前控制表明确
选用630/646，保持独立下返和不同底高，给固定侧后下边界留余地；不是运行
失败后的自动修补，也没有改相机或把表面截齐。以后任何改参须作为新版本
记录，不在一次受限试验中循环选最好图。

## 一次网格构造与克制分面

- 18米规则小域中的密度只驻留内存，确定性六四面体剖分，共享网格边交点
- 原始单壳做边/绕序/连通/重复面/重复坐标/顶点link等基本检查；不称完整自交证明
- 原生Blender只做一次Collapse，目标1600三角，无对称、Smooth、Subdivision
  或重复自动修复。保持平面着色，短肩由实际体量产生，不靠噪声或法线贴图
- 减面后复核基本拓扑、最长边85米，并记录原壳顶点→成品、成品顶点→原壳
  最近表面抽样；两向上限16米，指定暴露冠/肩/腹极点抽样上限9米
- 这些距离只约束**已提取原壳的保形**，不证明到连续解析场的距离、连续
  Hausdorff、自交、谷带宽度、飞艇路径或视觉通过。18米提取自身也有离散误差

每个控制保留为命名Blender Empty：平移/旋转/缩放改变中心/主轴/半轴，
`field_strength`改变局部强度。源内嵌控制JSON、纯numpy场脚本及
`EDIT58G_rebuild.py`。用户显式运行该文本即可从Empty重建，不需外部文件；
不会自动执行、保存或渲染。显式重建会替换该云壳的手工顶点编辑，源内有
相同警告。最终网格也可直接编辑，并保留各核贡献的八个顶点组。
重建要求Object Mode；有旧G表面时，失败的新候选不会自动删掉旧表面。

源只含一份最终网格、八个Empty、两相机、原光材与三个小文本；不保存密度
栅格、原始高模、缓存或贴图。预计压缩`.blend`可在200KB内，但必须实际核验。
硬门采用更严格的**200000字节**：超限保留源与真实失败报告，停止后续图；
不会删除控制或偷偷换小模型。仅抽样几何或机位门失败亦保留源并停止。
若减面操作本身抛错，保留日志/提取身份和可重建控制检查点，不把可再生的
原始高模写入`.blend`；报告会明确没有成品网格。

## 固定两机位与真实原PNG

直接从已冻结`revision-e/B_staggered_crowns.blend`只载入两相机；与其原生
build-result的matrix_world/projection逐项等值验证，不调用自动取景。

- 1216-source-front：836×471，像素比942/941；原透视机位，记录裁切而不换镜头
- shared-side-back：836×586，原正交机位，所有实际成品顶点仍须至少7%留边
- 沿用原中性材质、太阳/世界、Standard、曝光0、gamma1、CPU2、8samples、
  无去噪。每图独立新进程重开同一源，核mesh/编辑组/控制/文本/机位/光材
- 直接输出RGB8原PNG，关闭compositor/sequencer，无滤镜、重采样或像素编辑；
  wrapper只读检查CRC、尺寸、解压字节长度和SHA

保存前后与每个新进程都绑定源SHA；渲染不另存源。两图完成也仅是CPU源资产
研究，必须逐图实看，不能凭计数或留边晋级四根、Game61或全世界验收。

## 准备与受限执行

静态准备命令（不调用Blender）：

```sh
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python3 -B \
  source-assets/cloud-bank58/revision-g/check_preparation58g.py \
  --write-preparation-report
```

仅父任务在正式orbit窗口之后明确排程才可执行以下一次试验：

```sh
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python3 -B \
  source-assets/cloud-bank58/revision-g/run_patch58g.py \
  --run-approved-patch-trial
```

工作目录为仓库根。wrapper创建唯一证据目录，顺序build→front→side-back；
wrapper与子进程共用最多两核亲和性、线程2、总试验30秒；采样wrapper＋child
合计RSS并以各自真实峰值之和作保守1.5GiB门。哈希流式读取，触限立即杀
进程组并保留终态。每阶段以wait4记录真实退出、CPU时间与峰值，保留stdout/
stderr、输入SHA、源身份与原PNG。所有旧C/D/E/F/F2保护项及G准备输入逐项核
SHA。首个失败立即停止，不自动重试或绕过门限；已存在源或终态不覆盖。

本项没有最终几何/连续谷面/实看造型/世界集成/硬件GPU验收，也不触碰待确认
的旧E/F2 Slack内容。

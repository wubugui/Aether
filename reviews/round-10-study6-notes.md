## 实际改善

- 首屏约 **x1170–1330 / y695–775** 的草顶开始成为横向面，前壁上缘不再完全由细高竖肋占据。western_slab 和 central_wall 使用五个横向站位，确实减少了局部连续窄条的读感；front_columns 仍是九个站位，不应把五站位说成整个套件都已简化。
- 约 **x1180–1290 / y755–855** 的较亮灰壁与 **x1300–1425 / y760–875** 的暗壁已有分区。分开墙色与草顶亮度比整块统一变亮更有针对性。
- shadow_buttress 给左下增加了独立暗部实体，但当前仍被许多斜向灰片分割，尚未成为参考 **x1000–1220 / y800–941** 那种连续的深绿灰山腹。
- 侧后视图显示模型有屋脊到肩坡再到地面的体积。此处的问题已转为断面展开方式和大面组织，而非依靠增加模型数量解决。

## Crown：窄与长的具体来源

study6 的 `make_crown()` 中，`shoulder=ridge.copy()` 和 `rear=shoulder.copy()` 只更改 Y/Z；所有八个对应站位的 X 保持不变。按脚本的固定机位测量公式独立计算：

| 实际量 | study6 数值 |
|---|---|
| 顶脊 X 范围 | **127.14–209.66 m**，宽约 **82.53 m** |
| 顶脊 Z 范围 | **-64.83–-20.67 m**，深约 **44.16 m** |
| 主峰 | 约 **(164.82, 82.00, -42.62) m** |
| 主峰对应后肩（地形钳位前） | 约 **(164.82, 60.00, -81.62) m** |
| 主峰对应后脚 XZ | 约 **(164.82, -126.62) m** |
| 对应顶点到最远后脚的后撤 | **84 m**，X 横向位移 **0 m** |

这不意味着整个物体没有宽度：它的横向总宽超过 82 m，底部也很深。问题是各条从顶到脚的断面沿相同 X 纵向展开，顶脊到后肩没有形成偏心的横向凸肩。于是很大的底面积表现为长坡，无法转化为中高部的侧向厚度。侧边闭合带只横向偏移约 2–6 m，也主要是在封闭边缘，不能替代主要肩部体积。

在实际侧图约 **x775–900 / y355–590**，高灰肋仍很窄；它接向约 **x600–790 / y390–560** 的大片绿色长斜面。背图约 **x810–1025 / y375–560** 仍有单块醒目的长坡/楔形体。更长的后脚和更大的总 AABB 无法关闭这些视觉差异。

另一个原因是 `section_volume()` 将每对相邻行/列直接以两三角连接。当前后肩到后脚的 Z 距离可到 **45 m**，内部没有另一个真实转折坡或凹谷站位。交替对角线只是换了面片划分方向，不会生成新的肩部或侵蚀沟。大片面的法线相近，再按面烘焙光色，长楔形就更明显；不能把它归结为颜色一个问题。

## 下一步具体大形调整

1. **固定开场主峰 (1398,624) 和前壁边界，优先调整遮挡较少的后肩。** 后肩中段抬高约 6–8 m 可增加中高部截面，是可试的方向；但必须同时看 Y≈55/65/75 m 附近的水平截面，检查是面积和短轴增大，还是整片坡只被抬高。将后肩 X 做偏心变化也合理，但均匀 +10 m 主要是平移，1.08 缩放只给原本 82.53 m 的 X 总宽增加约 **6.60 m**，不能预判已经足够。

2. **把偏心肩做成几个不同位置的宽凸肩，而非整排一致偏移。** 可先保留峰顶和前缘，让主峰两侧的中高肩部分别在 XZ 中展开约 **10–20 m** 的可调量，端部渐收；再依据新侧图判断是否需要更大范围。中段应有一处肩部偏向侧后方、另一处下降成鞍部，避免八条断面仍平行。这里是建模试验尺度，不是已验证的最佳参数。不要仅把后脚继续拉远。

3. **在过长后坡中安排真实的转折肩或谷底，减少完整长直坡的面积。** 对 30–45 m 的后肩到脚段，可增加一行约位于中段的空间控制点，改变高程和横向位置，使其成为 15–25 m 左右的两个不同坡段；不是把原三角共面细分。该行无需贯穿全部八站位，更不应形成整齐水平腰线。保留宽面，避免重新变成均匀碎三角。

4. **首屏草顶继续向参考的宽台肩靠拢。** 参考约 **x1235–1415 / y685–760** 的黄绿平台面积仍比 study6 更连续；当前中央还有由高峰向下串联的深绿条。增加中间平台的实际纵深，让它遮住部分下方竖肋，同时保持前壁露出约 **x1180–1300 / y750–855**。草色不能按整条连接带机械赋予陡壁，需检查该条面法线和坡度，避免竖面染草色。

5. **统一左下山腹的大坡面方向。** shadow_buttress 和邻接块之间应形成几块相互衔接的宽暗坡与凹谷；首屏 **x940–1200 / y800–941** 目前仍有多条细长灰三角和色带。先检查不同模块彼此的实际遮挡和坡脚连接，再调暗色；不建议通过全局减亮来掩盖这些边界。

## 接地与验证脚本的边界

study6 的脚线点确实调用了 `ground_at()` 并下埋 1.2 m，但点之间直接连接为长边。它没有验证边中点及跨越不同地形三角后的接触，更没有验证下部三角整面不露空。侧图局部暗缝/突变与实现者指出的接地问题一致；本次不把“脚线顶点贴地”写成“整个脚线与地形验证通过”。

`verify_cliff_sections_prototype.py` 重算法线，并检查非二流形边与零面积面；它输出体积，但断言只有 `not bad and not deg`。这可支持生成前网格的边连通性检查，**不能证明体积正值、没有自相交、埋底扇面始终位于足迹内部、真实 GLB 导出重载无误或实际碰撞正确**。此外，颜色是按角色和几何面法线写入顶点色；大色块既可能来自角色分带，也可能来自真实宽面朝向，要先明确是哪个原因。

正式集成前，应对导出的独立 GLB 重读验证，并针对更新后的实际 Godot 组合地形检测脚线分段与三角内部。study7 的 4 m 补点有助于缩短跨地形长边，但仍需实际面内部/边采样和侧后图确认；它本身不自动等于接地通过。原型预览不能替代正式保存/重载、模型导入、碰撞和自由飞行测试。

**局部审查结论：保留五个完整断面原型的方向，继续修中高部肩宽、长坡结构和实际接地。首屏与侧后同时仍未通过，不做正式集成完成声明。**

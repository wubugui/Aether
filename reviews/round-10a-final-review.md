## 可确认的改进与不能沿用的旧原因

- **crown 不再是 study6 的同 X 后肩。** 当前后肩 X 为相对资产原点的 **1.25 倍展开并偏移 +26 m**，后撤深度已改为较平滑的 **32–45–38 m**，主段抬高，并在后肩到后脚之间增加真实非共面的低台肩/谷线。侧图约 **x635–800 / y330–535** 的肩部体积比 study6 明显增大；不能继续以“只拉长底部而未增厚上部”完整解释当前模型。
- **宽草顶、亮壁和暗壁有了实体与颜色分区。** 首屏约 **x1170–1330 / y695–775** 开始读成草顶覆盖壁体，约 **x1180–1290 / y755–855** 的亮灰壁与 **x1300–1425 / y760–875** 的暗壁已能区分。分开调墙色和草顶亮度的方向保留。
- **正式资产的中心扇形封底已替换。** `section_volume()` 现在用实际上表面拓扑的 XZ 投影反向封底。生成器已加入正体积阈值和非退化断言，不能再引用临时 verify 脚本“仅打印体积不断言”来描述这版正式生成器。
- **固定脚线每约 4 m 补点，而不是上部均匀加碎面。** 新点采样地形并向下压，保留宽壁的上部拓扑；这解决的是长边接地采样不足的一部分，仍不能自动证明整条边和底部面完全贴地。
- **独立组装边界继续成立。** 只选择五个资产导出各自 `.blend/.glb`，Godot 更新对应 prefab 和派生碰撞，没有把整世界重新导出为一个模型。

## 首屏与多视角仍存在的主要差异

### 1. 草顶与壁面仍不构成参考中的大块地貌

参考约 **x1235–1415 / y685–760** 有更连续、横向展开的黄绿台肩，覆盖下方几块宽壁。10a 该区域仍被较窄的绿条、尖肋和高峰下延的面带分割。下方约 **x1180–1300 / y750–855** 应出现主要宽暖灰壁，当前仍像多条薄柱并排；约 **x1300–1390 / y765–900** 的深色内壁/沟腹也较破碎。

下一步优先调整草顶的真实前后纵深、局部鞍部和遮挡关系，让几个较宽壁块露出，再处理窄裂隙。不要继续主要靠各条面的配色去伪造平台。首屏大面宽度可以先按 **60–110 px 的不等宽面群**检查，但这些面群应来自完整岩壁断面，而非单张面片。

### 2. 左下山腹仍由长灰三角和硬色界主导

参考约 **x1000–1220 / y800–941** 是连续的深绿灰山腹，并由几块厚实坡面转折构成。10a 约 **x940–1200 / y800–941** 仍可见明显长灰三角、细绿色斜带和相邻模块硬接缝。shadow_buttress 已是独立实体，但其暗色面积和形体连接没有形成该整体关系。

应调整 shadow_buttress 与 western_slab、front_columns 的相接面和遮挡，把几条细长坡带合成几个不同方向的宽凸坡与凹谷。保留完整山脚和背面；不能通过整体变暗掩盖模块交界。

### 3. Crown 从长楔变厚，但侧后仍过于像一个规则高块

增厚是真实进步。当前背图约 **x795–980 / y375–615** 出现较醒目的单个高绿色块体；侧图高灰面仍集中于约 **x775–900 / y355–590**，周围大坡面的转折比较机械。需要让相邻肩部的高程、侧向凸出和鞍部位置更有区别，避免整排断面通过统一变换后形成一个规则高块。

目前不建议再统一加宽或拉长整个 crown。保留开场主峰约 **(1398,624)**，优先用几个中高部水平截面与侧图检查局部短轴宽度，调整个别肩峰、转折和坡脚。参考没有提供背面，因此侧后审查只能要求自然、完整且可飞行的三维形体，不能虚构背面的像素匹配目标。

### 4. 颜色面积仍明显不同，局部平均色不能替代材质取样

本 run 的前景 ROI 为 **[1070,622,1672,941]**。参考平均 RGB 为 **(126.808,133.674,112.671)**，10a 为 **(138.810,146.969,117.831)**，即该范围整体仍偏亮约 **12.0 R / 13.3 G / 5.2 B**。这混合了草、岩、阴影和背景的面积差异，不能直接把每块材质减去这一数值。

先恢复草顶、亮壁、暗壁各自的掩模，再在对应面内比较颜色。上方草顶应保留参考的黄绿亮面，下方山腹增加连续的暗部；避免将整个 foreground 一起压暗。

## 局部更新器：保留原生编辑的范围与两个实质缺口

`model_cliff_kit.py` 在开始改资产前检查 `--` 后的资产名称集合。`install_cliff_kit.gd --asset=...` 清空地形更新列表、过滤 kit；保存原生 World，并在刷新中保留 prefab 节点的变换、材质覆写和自定义字段，仅重建派生的三角碰撞。碰撞点经模型节点到 Collider 的完整变换转换，方向正确。World、目录、受影响派生资源有备份，改动过的 MultiMesh 保存到独立资源文件。

但是 `changed_bounds` 仍有两个可从源码直接确认的编辑边界缺口：

1. **只覆盖新 AABB，漏掉旧足迹。** 范围在模型刷新后从新 mesh 取得。若后续模型缩小或足迹移位，原来站在旧模型上、如今落在新 AABB 外的植被不会进入射线重贴，可能停在旧高度。应在刷新前保存旧范围，并使用新旧范围的并集；再次运行得到 0 漂移不能证明范围外没有漏检。
2. **只按固定节点名定位一个实例，漏掉用户复制/重命名的 prefab。** 当前循环访问 `<category>/<item.name>`，并未按 `scene_file_path`/稳定资产身份枚举全部实际实例。同一 prefab 的其他实例会跟随导入资源换几何，却没有相应重贴范围；若模型原点将来改变，它们也不会获得同样的原点补偿。应覆盖所有实际实例和变换，并包含首次新增实例的范围，不能只依赖原始布置时的命名。

这两项不否定本轮五个原始实例的刷新结果，但必须在后续编辑工具验证中补足。实现者报告的首次 5 个植被实例/2 组重贴与最终 0 漂移，属于这一次布置结果，不能替代缩小、复制、重命名、移动父节点后保存重开等场景的验证。

## 几何检查与本次 GPU 范围

已读取 `captures/round-10a-section-overlap-check.json` 和检查脚本，并逐项比较其中五个 GLB SHA256 与当前实际导出资产，**全部一致**。报告的五项均无向下非底面；上表面投影重叠分别为 0，western_slab 仅有约 **4.55×10⁻¹³ m²** 的浮点残差。该检查结合无重叠顶面投影封底的新实现，支持关闭已发现的中心扇底重叠问题。

这项检查限定于单个导出资产的上表面投影/朝向，不检测不同实例之间的交叠或实际地形接触。脚线约 4 m 采样、生成器闭合/体积断言、18 个资产的导出几何检查应分别表述，不能合称任意情况下绝无自交、无地缝。

本次 scoped-driver 明确设置 `release_validation=false`，范围是四视图、参考指标、源工程游戏检查、岩崖接触、绕崖以及导出地貌检查；没有 Windows 导出，也没有重新执行长距离加载/路面验收。**后续已读取最终归档：进程退出 0，9 个阶段全部通过，manifest 为 passed。** 源工程 **36/36**、实际飞艇岩崖接触 **21/21**、独立导出地貌 **18/18**；绕崖 **6 个航点、1,148.1486 m**，最小采样离地 **54.2604 m**，相机遮挡样本 **0**。此范围不等同贴壁飞行、全部地形接缝或本版 Windows 发布复验，视觉打回结论不变。

另一个自动化边界：scoped-driver 会把已有的 section-overlap JSON/脚本复制并绑定到 run，却没有把该 JSON 的 passed 和逐资产 SHA 校验纳入 `stage()` 的自动必过条件。本次由审查手动核对了它与五个当前 GLB 的一致性；后续复用此流程时，应在 driver 中明确验证，避免绑定了旧报告却误认为进行了本次检查。

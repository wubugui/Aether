# 16b 陡草面定位，供16c塑形使用

本次只读解析实际16b GLB，并对七件cliff实际三角做少量CPU射线定位；没有改源或启动Godot/Blender。依据为 `captures/foreground_study_16b/cliff_crown.glb`，SHA256 `074f738f28d1d29ff6d60afce6e78411101e70fb27c8c4edf5b9f0ddffbc0bfa`。面序号为该GLB primitive的零基三角序号，列号为零基。视觉结论继承本轮实际三视图审查：仍打回。

## 两张陡面对应关系

面23（52.7045°）：`front[3] → shelf[2] → front[2]`。

面573（51.4973°）：`front[3] → shelf[3] → shelf[2]`。

两面共用 `front[3]—shelf[2]` 对角，不是不同位置的独立缺陷。此前重心投影约(1363,712)、(1378,705)。它们处于同一个第2–3列台肩四边形内部。

第2与第3列各自front→shelf的5.26°、8.88°确实很缓；但相邻列整体同时向后错位并下降约6m。共同对角几乎无X距离，却在约10.57m水平距离内升9.15m。面法线由完整二维关系决定，因此拼成52°左右的两张陡面。

建议先调整这一整块四点关系：缩小相邻列横向高差，重新组织前后错位，同时保护新台肩与上方裸岩之间的实体坡折。不能只让shelf再次贴近front等高、继续加长两条纵剖线，或者只换四边形对角线；这些操作可能降低一个数值却保留整块的陡倾与尖角。应结合开场草肩前缘和側面后退裸岩关系决定最终点位，坡度达标不等于视觉通过。

## 加宽草肩时的资产归属边界

本审查此前已经实际看过参考和16b开场/侧/背图。大区域仍需分别修改：左前方草肩与暖灰宽壁并不全属crown；下方暗沟也不全属crown。为避免仅凭模型名字猜归属，本次将16b三件模型替换进七件cliff清单，采用 `assets/cliff_kit.json` 平移和作者固定相机 (0,145,250)、FOV50°、pitch−3.526°，对实际GLB三角求最近射线命中。

**这是仅七件cliff之间的最近曲面，不含地形、UI、树木或建筑，也不是GPU对象ID拾取。** 不把它直接称为最终像素所有者；图中植被遮挡和与地形的接触仍须实际渲染判断。

| 开场采样像素 | 七件cliff中最近曲面 | 对塑形的意义 |
|---|---|---|
| (1200,760)、(1220,750) | western_slab，前方遮住front_columns | 左上边缘并非全由front_columns控制 |
| (1235,710)、(1250,720)、(1250,745)、(1270,740) | western_slab | 参考x1235附近草肩展开，应检查western_slab和地形；扩大crown去覆盖它可能只是遮住另一个错误 |
| (1250,795) | front_columns | 该处暖灰壁主体不能归给crown |
| (1290,750)、(1305,780) | central_wall，略在crown之前 | 左侧内沟入口/上缘需要检查两件接触，不能只移动crown前沿 |
| (1320,760)、(1340,750)、(1360,770) | crown，挡住后方central_wall | 同一暗壁区域的上部又是crown；仅按矩形ROI给central_wall归因会错 |
| (1370,810)、(1400,840) | central_wall | 下方暗壁与凹沟需要它的实体宽度/坡折支持，加宽crown可能遮掉本应看见的沟壁 |
| (1270,710) | 未命中这七件cliff | 此处不能据空白命中改crown，须检查地形与其他实例 |

基于实图和上述范围，16c优先解决crown第2–3列局部尖折有明确依据；向左扩展到x1235–1270时应转查western_slab的上坡与地形，向下改暗沟应结合central_wall，避免一个crown表面包住所有需要不同纵深的资产。现有报告只指出修改依据，不声称16c已经实现或已达到参考。

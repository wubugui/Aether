# Godot 模块化游戏工程审查

**新增硬性门槛：世界必须由 Godot 中可编辑、可复用的游戏资产拼装。模块化合格与画面精确恢复必须同时成立，互不抵扣。**

这是拆分进行前的代码快照审查；不是对正在改造的新文件预先判定。已读取 `scenes/game.tscn`、`scripts/open_world.gd`、`tools/create_game_scene.py`、`blender/build_open_world.py`，以及当前 `scenes/` 和 `assets/models/` 清单。

## 当前明确欠缺

- `game.tscn` 仍直接引用 `assets/open_world.glb`，作为 `World/Terrain` 的一个整体导入资产。GLB 内部确有多个地形网格，**并不是只有一个 Mesh**；但独立地形模块资源、对应 Godot 地形场景和显式世界实例尚未体现。
- 房屋、城堡、树木等已有独立 GLB，这部分可保留。运行时却先 `instantiate()` GLB，只拿 `first_mesh().mesh` 后释放原场景，再用 `new_model()` 创建裸 `MeshInstance3D`。这没有保留可复用游戏预制体的子节点、局部材质、碰撞、连接点和交互属性。
- 世界布置主要读取 `world_layout.json`，在 `_ready()` 用 `add_child()` 临时创建。当前代码未给这些编辑器生成节点设置持久场景 `owner`；`@tool` 能预览不等于编辑后能保存、重开且保留修改。
- 当前仅见总游戏场景和旧预览场景，缺少明确的 Godot `world.tscn`、地形块场景、飞艇场景和建筑/港口等游戏资产包装场景。
- `tools/create_game_scene.py` 输出“independent assets”文字不能证明模块化；必须查看生成后的真实节点/资源引用。现有 `verify_world_assets.py` 仍以单个 `open_world.glb` 为固定输入，不能验证新架构。

## 改造后必须逐项验证

- [ ] **建模与拼装职责清楚。** Blender 导出飞艇、建筑、云、树、岩石及独立地形/地貌块；Godot 保存世界布局、材质覆盖、碰撞、LOD/可见距离和游戏交互。可以用脚本批量生成场景，但最终产物必须是真正可编辑的 Godot 场景。
- [ ] **地形是真拆分。** 每块有独立网格资源及 Godot 场景，世界场景显式实例化并保存变换；移除一块不会删除整个世界。块的局部原点合理，边界、法线、碰撞和道路跨块连续。禁止给同一个整世界 GLB 套多个空节点声称已拆分。
- [ ] **游戏资产有可复用 PackedScene。** 至少飞艇、主要建筑、港口、风车、航标、各主云拥有合理的 `Node3D`/物理主体根与模型子节点；模型重导入不会抹掉 Godot 的行为和参数。每个建筑不必强行独立编写脚本，但实例应能保存自己的身份、变换和所需交互数据。
- [ ] **真实组装树可见。** 打开世界场景时，编辑器本地场景树能明确看到 Terrain、Landmarks、Settlements、Clouds、Vegetation、Water 等对应实例/组；不能只有运行后才出现的整世界。层级名称可以不同，职责必须能辨认。
- [ ] **预制体保留完整结构。** 不再通过 `first_mesh` 扔掉资产层级。有活动桨叶/风车叶片/旗帜、灯光、停靠点或碰撞的资产，这些子节点在实例后仍然存在，局部坐标一致。
- [ ] **植被可继续使用 MultiMesh。** 不要求把上万棵树全部做成场景树节点；但应按块/树种保存 Godot MultiMesh 资源或可编辑布置数据，有明确再生成流程。能删除/移动一组或改变一处布置并保存，碰撞与视觉位置一致；不能每次打开就无条件覆盖编辑结果。
- [ ] **编辑器修改能持久化。** 在临时验收副本中移动一间房屋、旋转一个岩块、修改一个港口的参数，保存、关闭、重开并运行，确认修改仍在，且碰撞与停靠点一起移动。仅代码静态检查或远程运行场景树截图不足以证明这一项。
- [ ] **复用能工作。** 在临时验收副本中实例化第二间同一房屋、第二个港口/风车，分别修改实例参数；不会共享错误身份、动画状态或可变资源，不会让另一实例同时移动。
- [ ] **导入与布局互不破坏。** 重导出某个 Blender GLB，Godot 重新导入后，世界实例位置、Godot 材质/碰撞/脚本覆盖仍保留。世界场景的手工修改不会被启动时从旧 JSON 静默重置；如需重新生成，必须是明确的重建操作。
- [ ] **碰撞由当前模块验证。** 每块地形与建筑/岩石的实际图形位置一致，停靠点属于正确实例。测试同一版本跨块飞行、绕山、碰撞、停靠和存档恢复；旧整包场景测试结果不能自动沿用。
- [ ] **主入口和正式包引用新世界。** `project.godot`、游戏场景、导出配置和实际 EXE/PCK 均采用新模块化世界；旧 `open_world.glb` 可以作为历史资产暂存，但不得仍是活动世界的依赖。
- [ ] **画面不回退。** 同一新架构运行版输出固定机位/时间开场、反向和山体侧后图；继续按原图轮廓、颜色、UI 及真实三维门槛独立打分。新架构做对也不能结束视觉迭代。

## 最小可复查证据

交下一轮审查时附：实际 `world.tscn` 与一份地形/港口/飞艇包装场景、编辑器本地场景树与选中实例的 Inspector 证据、上述保存重开及复用操作的结果、当前运行渲染和同网格碰撞验证。不要以文件数量、资产命名、节点数量或一张编辑器全景图代替可编辑性验证。

在这些证据形成之前，新增的模块化工程要求维持 **未通过**；原有画面要求也维持 **未通过**。

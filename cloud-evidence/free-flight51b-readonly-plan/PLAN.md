- Game51b root uses scripts/game42b.gd, inheriting scripts/game.gd. Airship is CharacterBody3D; airship_body.gd assigns visual materials, while game.gd owns flight physics.
- Normal ready resets to HOME_SHIP=(-4.15,136.8,184), heading=0, model yaw=13 degrees, throttle/speed/vertical speed=0, anchored=true, photo_mode=false. It loads progress metadata but not saved position (load_progress(false)), creates HUD/audio, and applies environment reference1343. No free-flight input is needed to unpause this normal start.
- There are no custom InputMap actions. Flight polls physical W/S, A/D, E/Q and Shift. W raises throttle and S reduces it, at .34/second, clamped 0..1. Releasing W keeps throttle; S does not reverse. A/D rotate at +/- .66rad/s (boost .52). E/Q command +/-42m/s vertical (boost75) with 26m/s² acceleration/deceleration. W, turn or lift automatically release anchor; S alone does not.
- Normal horizontal target is throttle*88m/s; acceleration11m/s². Shift raises target to175 and acceleration17. Space toggles anchored; entering anchor sets throttle0 and decelerates at26m/s². It is not an instantaneous position freeze. With max normal speed88, braking alone can require about149m; avoid full throttle in the small lake test.
- Each actual physics tick writes velocity then calls airship.move_and_slide(). Model forward is -global_basis.x. motion_mode=FLOATING, max_slides8, safe_margin.07. Saved body layer2, default mask1; active solids must carry layer1. Envelope ConvexPolygonShape3D and hull BoxShape3D(8.3,3.1,2.8), local y=-2.3, are the two body shapes. These do not prove every decorative extremity has a collision shape.
- Active terrain and sea layers include layer1; world.update_focus runs every .2 simulation seconds and determines nearby terrain/prop colliders. The camera alone ray-tests its follow/orbit segment; a clear camera ray is not body clearance.
- Collision impact can damage shield/health; death can teleport to a rescue port. A valid short control test must report zero collisions/damage/rescue, not merely positive displacement.

## Reference mode and exit semantics

- [ and ] call observe_reference(): fixed camera, prescribed airship placement/yaw, photo_mode/reference_observation=true, velocity/throttle/vertical speed0, anchored=true, autopilot=false. This function teleports to a reference; it is a setup/navigation operation, not a flight.
- F2 is the actual exit: base input toggles photo_mode=false, derived input clears reference_observation, normal physics and following camera resume from the prescribed ship location. Heading was synchronized to ship yaw. No old pre-observation location or camera is restored.
- W alone while observation is active does not resume physics. Esc clears help/map/orbit but does not exit observation. R resets home/body/camera but does not clear photo_mode/reference_observation; R inside observation therefore does not reliably resume flight. Exit with F2 first, then R if desired.
- FOV also persists from observation; reset_flight does not reset it to the saved Camera FOV50. This is existing behavior to record, not silently fix in the test.
- C toggles cockpit and hides external Visuals; right-drag/wheel orbit/zoom existing follow camera. F4 autopilot tour is separate and must remain off in this test. F5/F9 save/load are excluded from the short control test.
